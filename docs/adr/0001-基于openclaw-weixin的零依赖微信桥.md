# 0001. 基于 openclaw-weixin 的零依赖微信桥

- 状态：已采纳
- 日期：2026-11-07

## 背景

要把微信接入超级助理（`dsh-my-superagent`，协议 `my-superagent/v1` 的 IM 桥），需要一个能扫码登录、长轮询收消息、主动发送的微信协议客户端，以及把交付与主人消息在核心和微信之间互转的桥适配。约束：

1. 仓库与生态约定零运行时依赖（只用 Node 内置模块），与 `dsh-im-infoflow` 的工程门禁保持一致；
2. 不引用、不复制任何第三方 DSH 微信插件的代码，协议事实需要有权威出处；
3. 微信走腾讯 iLink 协议（长轮询外拨，不需要公网 IP），协议的权威参考是腾讯官方 `openclaw-weixin` 实现（MIT）。

## 决策

- 协议客户端**参考腾讯官方 `openclaw-weixin` 的接口与协议定义自写**，不把该包或任何第三方实现作为运行时依赖；类型定义、端点、消息形态以官方实现与真机实测为准，出处记录在各实现文件与本 ADR。
- 插件结构与构建门禁**与 `dsh-im-infoflow` 同构**：两半式（host tsc 逐模块 + client esbuild 单文件）、`scripts/build.mjs` + `scripts/verify-package.mjs` 门禁、`npm run check` 提交前必跑。
- 独立仓库 `dsh-im-wechat`，只经结构类型与 `my-superagent/v1` 协议和核心对话，不 import 核心包。
- 桥遵守协议分工：不解析命令、不判断身份，只做呈现与转发。

## 后果

- 协议演进要自行跟随官方 `openclaw-weixin` 的版本节奏同步（接口变更需实测核对）；
- 协议层工作量集中前期（登录、长轮询、媒体加解密），但换来依赖干净、许可清晰、不受第三方插件生命周期影响；
- 构建与验证路径与 infoflow 一致，评审与发布流程可直接复用既有惯例。
