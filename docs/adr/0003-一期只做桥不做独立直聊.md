# 0003. 一期只做桥，不做独立直聊

- 状态：已采纳
- 日期：2026-11-07

## 背景

`docs/local/20261107-背景与交接.md` 留了一个待定项：是否给本插件加「独立模式」——不接核心、自己起一个会话直接和主人聊。协议本身允许（桥可以不接入核心照常工作），如流桥也没有做独立模式。

独立模式不是一个开关，而是一整套并行能力：会话状态、模型调用、工具执行、注意力调度、记忆，全都要在这条路径上再实现一遍；而且它和核心的会话是两份状态，主人在两边说话会得到两套互不相干的上下文。

## 决策

**一期只做桥，不做独立直聊。** 插件只在 `mySuperagent` 服务存在时注册桥并收发消息；服务不存在时插件照常加载、面板照常可用（能看到「未接入核心」的状态），但不起自己的会话。

这带来两个具体约束，写进实现：

1. `mySuperagent` **不写进顶层 `inject`**。写进去会让没装核心的组合整个插件不激活，连带面板也不可用；改用子 fiber 的 `ctx.inject(['mySuperagent'], …)` 注册，核心卸载时注册随之撤销。
2. 没接入核心时，入站消息**不丢也不回**：仍然更新登录态与连接状态，但不向微信发送任何内容（桥的身份只来自核心的 `deliver`），也不自行解析命令。

## 后果

- 范围收敛到「协议客户端 + 桥适配 + 面板」，工作量与如流桥同量级。
- 主人在微信里看到的一切发言都出自核心，审计与注意力记账只有一处，不会出现两套记忆打架。
- 真要做独立模式时，接缝是清晰的：新增一个不依赖 `mySuperagent` 的会话端口，把 `inbound.ts` 的产物交给它；协议层与呈现层不用改。
