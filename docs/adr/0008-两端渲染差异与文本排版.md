# 0008. 两端渲染差异与对外文本排版

- 状态：已采纳
- 日期：2026-11-08

## 背景

同一条文本，微信 PC 端与手机端渲染结果不一样。2026-11-08 用真实机器人给主人的微信发对照消息，逐项测出来（微信 Mac + iOS，PC 端窗口标题旁可见「对方正在输入」）：

| 发出去的文本 | PC 端 | 手机端 |
| --- | --- | --- |
| `第一行\n第二行\n第三行` | 挤成一段，换行变成空格 | 逐行显示 |
| `第一行  \n第二行`（行尾两个空格） | 仍然挤成一段，硬换行无效 | 逐行显示 |
| `第一行\n\n第二行`（空行分段） | 分成两段，但每行之间多一条空行 | 分成两段 |
| `- 第一行\n- 第二行` | 渲染成紧凑的无序列表 | 原样逐行显示 `- 第一行` |
| `1. 第一行\n2. 第二行` | 渲染成紧凑的有序列表 | 原样逐行显示 |

结论：**PC 端按 Markdown 渲染消息体，手机端按纯文本渲染**。于是原来按「纯文本」拍平后用的 `• ` 子弹符在 PC 端失效——列表挤成一整段，而手机端看着正常；`/help` 这类输出在 PC 上就是灾难。

## 决策

- 对外文本继续**拍平行内 Markdown**（加粗、链接、代码、标题符号）：手机端不渲染，留着只会把原始语法露给主人；PC 端虽然会渲染，也不为了 PC 好看而牺牲手机端可读性。
- 唯一的例外是**列表符号**：`- `（无序）与 `1. `（有序）保留 Markdown 语法，因为它是「PC 端紧凑分行、手机端原样逐行」的唯一两全写法。原来把 `- ` 改写成 `• ` 的规则删掉。
- 新增 `normalizeBlocks`（`src/host/superagent/render.ts`）统一两端换行：
  - 列表项之间、列表前的引导行之后 → 保留单个换行（PC 端认列表，手机端本来就逐行）；
  - 非列表行之间 → 补空行（PC 端只有空行才分段）；
  - 列表结束后的第一行 → 补空行，否则会被 Markdown 吞进上一条列表项；
  - 行尾空白清掉，首尾不留空行。
- 不再使用行尾两个空格的「硬换行」写法：实测 PC 端不认。

## 后果

- `/help`、状态摘要这类分条输出在 PC 端恢复成紧凑列表，手机端从 `• ` 变成 `- `（可读性相当，且与 PC 端渲染出的列表符号观感一致）。
- 纯文本多行内容在两端都变成「段落 + 空行」，比原来在 PC 端糊成一段可读；代价是手机端也会多一条空行。
- 排版规则全部在 `render.ts` 里，用真实机器人发消息就能验证，不依赖客户端类型判断。
- 已知未验证：微信 Windows 客户端只测了「不换行 / 不认硬换行 / 认空行 / 认列表」中的前两项（PC 端为 Mac 实测），Windows 若有差异，调整点同样只在 `normalizeBlocks`。
