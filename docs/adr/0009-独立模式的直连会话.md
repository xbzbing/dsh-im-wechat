# 0009. 独立模式的直连会话

- 状态：已采纳（修订 [ADR-0003](0003-一期只做桥不做独立直聊.md) 的边界；下面的「只做文字」由 [ADR-0017](0017-独立模式的图片入站.md) 补齐）
- 日期：2026-11-08

## 背景

ADR-0003 一期只做桥：不装 `dsh-my-superagent` 时，插件只发提醒，入站自由聊天不回话。独立部署的主人（例如只想在手机上遥控本机 DSH，不上核心）因此用不了微信这一侧。

`dsh-im-infoflow` 的独立模式是反过来的做法：不开核心也能收发——入站消息在配置的工作区里建一个会话、把消息提交进去、把回答发回 IM，回合在跑时按「插话 / 排队」处理。微信这边要对齐同样的能力。

## 决策

- **两种模式互斥**：`ownFeaturesActive()`（启用 + 未接入核心 + 已登录）为真时才走直连；接入核心后这段整体沉默，消息由核心接手，避免一边回两次（与 ADR-0006 同一套判据）。
- **会话**：独立模式下第一次消息时，按配置的 `directWorkspaceId`（宿主工作区 id，走 `sessionController.create({ workspaceId })`；空表示宿主默认位置）新建一个会话并改名 `微信 · <账号尾号>`，之后一直用它。绑定落 `$DSH_HOME/dsh-im-wechat/direct.json`（`0600`），重启沿用；会话被删掉时由面板「重置绑定」或后续错误提示重建。
- **提交方式**：会话有一轮在跑时按 `directBusyMode` 决定 —— `queue`（默认，等这一轮结束）或 `steer`（插进正在跑的一轮，本轮回答仍由原回合送回）；空闲时一律 `queue`。运行态优先向宿主的 `sessionController.list()` 问，问不到就用 `turn/start`、`turn/end` 事件推断。
- **回复**：订阅宿主的 `session/event`，只认绑定的那个会话；`turn/end` 时把本轮最后一条 `assistant/message` 的可见文本按 Markdown 渲染、超过 1800 字分条发回微信。工具调用、思考过程不发。
- **只做文字**：图片入站仍要求核心声明 `owner-images`（ADR-0004），独立模式不下载、不转存。
- **输入状态照发**：独立模式的回合同样有会话在跑，受理入站后照常发「正在输入」（[ADR-0007](0007-输入状态.md) 决策里「只有接入核心时才发」一句由本篇修订）。
- **面板**：新增「独立模式」一组设置（工作区、插话开关、当前绑定会话、重置绑定），走新端点 `direct.set`；工作区**从宿主的工作区目录里选**（`workspaceRegistry.list()`，走新端点 `workspaces.list`），不让手写路径，选完由宿主校验 id 仍然存在。接入「我的超级助理」时整组置灰并说明原因——那种模式下会话与模型由核心决定。`status` 返回 `direct` 快照，`HOST_CONTRACT` 与客户端 `REQUIRED_CONTRACT` 一起从 2 加到 3。
- **不做的事**：不做命令解析（`/new`、`/stop` 之类仍由宿主或 Web 完成），不做多会话切换，不做群聊。插件仍然只是「把消息放进主人的会话、把回答送回来」，不是对话代理。

## 后果

- 不装核心插件也能在微信里用：扫码登录、选工作区、收发文字消息，回合在跑时可选插话或排队。
- 接入核心后独立模式自动沉默，主人的提醒与交付仍由核心发，不会两边各回一份。
- 会话绑定是「一个主人一个会话」：换工作区或想开新会话要点「重置绑定」，之后第一条消息按新设置重建。
- 工作区下拉依赖宿主的 `workspaceRegistry` 服务；组合里没有它时面板显示「宿主不提供工作区服务」，独立模式建会话走宿主的默认位置。
- 面板契约从 2 升到 3，旧面板连新 host 会提示重装；host 半改动仍要靠卸载重装生效。
