# 0010. 出站发图

- 状态：已采纳（上传与字段规格见 [iLink：消息与媒体](../protocol/ilink-消息与媒体.md)）
- 日期：2026-11-09

## 背景

主人在微信里让会话把画好的头像发给他。会话没有发图工具，只能把本地路径写成 markdown 图片；核心把这段文字原样发到微信，而桥按 ADR-0008 把图片整段丢弃。结果是主人只收到「A · Q 版抱鲸鱼，1024×1024」这一行字，图没到。

ADR-0004 当时定的是「入站做、出站不做」，并写明出站要加就复用同一套 CDN 上传参数与加密路径、届时另立 ADR。这份就是那一份。

## 决策

**做，走官方同一条链路**：`getuploadurl` 取上传地址 → AES-128-ECB 加密 → POST 到 CDN → 用响应头里的下载参数发 `image_item` 消息。字段级规格、`image_item` 的字段表与失败表现见 [iLink：消息与媒体](../protocol/ilink-消息与媒体.md)。

- **图片先于文字发**：文字里通常写着「图见上」，图没到就发文字会让人以为没发。
- **按张记进度**：交付里带 `images` 时按 `delivery.id → 已发张数` 记账，重试从下一张接着发，不重发已到的图。
- **能力声明** `capabilities.outbound.images = true`，核心据此才把图发过来（核心侧 ADR-0067）。
- **边界与下载同一套**：上传地址只允许 `https:` 且主机在微信域名内（`weixin.qq.com` / `qq.com` 及其子域），否则不发；4xx 立即失败不重试，5xx 与网络错误最多 3 次；缺 `x-encrypted-param` 视为失败。

`image_item` 的字段是硬的：多一个（顶层 `aeskey`）或少一个（`media.encrypt_type`）都会让 `sendmessage` 照常返回成功、核心回执 `sent`，而微信端什么都不显示或只出一个灰块。第一版正是照「社区实现」写错了这两处，靠真机反证才改对——所以这一层不做推断，只按官方实现逐字段对齐。

## 后果

- 主人在微信里能收到会话产出的图片。
- 上传是插件第二处主动对外请求的地方，域名白名单与下载共用一条规则，外部地址无法把凭据带出去。
- 图片走两段网络（先上传 CDN 再发消息），单张 10 MiB 上限沿用核心侧的约束。
- 图与文是两条消息：图先到，文字后到；客户端不合并成一条。
