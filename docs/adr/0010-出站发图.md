# 0010. 出站发图

- 状态：已采纳
- 日期：2026-11-09

## 背景

主人在微信里让会话把画好的头像发给他。会话没有发图工具，只能把本地路径写成 markdown 图片；核心把这段文字原样发到微信，而桥按 ADR-0008 把图片整段丢弃。结果是主人只收到「A · Q 版抱鲸鱼，1024×1024」这一行字，图没到。

ADR-0004 当时定的是「入站做、出站不做」，并写明「出站发图如果要加，需要复用同一套 CDN 上传参数（`getuploadurl`）与加密路径，届时另立 ADR」。这份就是那一份。

## 决策

**做，走官方同一条链路**（对照 Tencent 官方 `openclaw-weixin` 的 `cdn/upload.ts` 与 Dart SDK `weixin_clawbot` 的 `CdnMediaUploader`）：

1. `POST ilink/bot/getuploadurl`，带 `filekey`（16 字节随机数的十六进制）、`media_type: 1`、`to_user_id`、`rawsize`、`rawfilemd5`、`filesize`（密文大小 = `rawsize + 16 - rawsize % 16`）、`no_need_thumb: true`、`aeskey`（16 字节随机密钥的十六进制）。
2. 上传地址优先用响应里的 `upload_full_url`，否则按 `{cdnBaseUrl}/upload?encrypted_query_param=…&filekey=…` 拼。
3. 用该密钥做 AES-128-ECB + PKCS#7 加密，`Content-Type: application/octet-stream` POST 密文；下载参数在响应头 `x-encrypted-param`。
4. 发一条 `message_type: BOT`、`item_list[0].type = 2`（IMAGE）的消息，`image_item` **只放** `media` 与 `mid_size`：`media.encrypt_query_param` 放下载参数，`media.aes_key` 放 **base64(32 个十六进制字符)**，`media.encrypt_type` 固定 `1`，`mid_size` 放密文大小。**不要**带 `image_item.aeskey`（见下面的「修正」）。
5. 图片先于文字发：文字里通常写着「图见上」，图没到就发文字会让人以为没发。
6. 交付里带 `images` 时按张记进度（`delivery.id → 已发张数`），重试从下一张接着发，不重发已到的图。
7. 能力声明 `capabilities.outbound.images = true`，核心据此才把图发过来（核心侧 ADR-0067）。

### 修正（同日实测）

第一版按「社区实现」的说法，在 `image_item` 顶层另带一份 `aeskey`（原始十六进制），并且 `media` 里没有 `encrypt_type`。实测结果是：`sendmessage` 返回成功、核心回执 `sent`、微信端**什么都不显示**（不是报错，也不是「图片已过期」）。

回到官方实现（`openclaw-weixin` 的 `cdn/upload.ts` 与 Dart SDK 的 `CdnMediaUploader`）逐字段复核后确认两条硬事实：

- `media.encrypt_type = 1` 必须有：客户端按它去取「缩略图/尺寸元数据」那一层，缺了就渲染不出来；
- 顶层 `aeskey` 不能带：客户端认这个字段就直接拿十六进制密钥去解密，解得出来才怪，现象是一个灰块而不是报错。

也就是说：`aes_key` 只出现在 `media` 里，且只有 base64(十六进制字符) 这一种形态；`image_item` 多一个字段都会让客户端解不出来。ADR 原文「少任一项客户端会显示图片已过期」是把症状记错了，误导了实现方向。

**边界与下载同一套**：上传地址只允许 `https:` 且主机在微信域名内（`weixin.qq.com` / `qq.com` 及其子域），否则不发；4xx 立即失败不重试，5xx 与网络错误最多 3 次；缺 `x-encrypted-param` 视为失败。

## 后果

- 主人在微信里能收到会话产出的图片。
- 上传是插件第二处主动对外请求的地方，域名白名单与下载共用一条规则，外部地址无法把凭据带出去。
- 图片走两段网络（先上传 CDN 再发消息），单张 10 MiB 上限沿用核心侧的约束。
- 图与文是两条消息：图先到，文字后到；客户端不合并成一条。
