# 0011. 失败立刻提醒

- 状态：已归档（2026-11-10；判据移入 `AGENTS.md` 的工程约定与 `src/host/long-tasks.ts`，这里留原文备查，不再维护）
- 日期：2026-11-09

## 背景

独立模式（未接入超级助理）的长任务提醒只在「超过阈值」时发，且把 `aborted` 一律当作主动终止。模型报错、provider 断网、额度用尽这类失败，短任务完全不提，长任务还要等 60 秒静默——主人只看到「已发出」，之后没有下文。

宿主事件实测形状（核心仓库 ADR-0070 记了统计）：`{kind:"error", error:{message}}` 是失败；`{kind:"aborted", reason:{kind:"user"}}` 才是主人自己停的。

## 决策

- 主人自己停的（`reason.reason.kind === 'user'`）不提醒。
- 其余 `aborted` 归入失败；`error`、`blocked` 同样是失败。
- 失败**立刻提醒**：不看阈值、不看主人在这一轮里是否插过话、不受「长任务提醒」开关影响。开关只关「完成」提醒。
- 提醒正文带原因原文：`原因：当前请求的额度已用尽`；没有原因就不留空行。
- 标题从「长任务提醒 · …」变成「任务失败 · …」，一眼能看出是需要处理的事。
- 关闭开关后仍跟踪会话事件（只为失败提醒），`configure(false)` 会清空已有记录。

## 代价与取舍

- 短任务失败也会发消息，比原来吵一些；换的是「不再没下文」。
- 关闭开关不再等于完全静默：失败仍会来。有意的。
- 关闭瞬间正在跑的那一轮，其失败不会提醒（记录已被清空）。
