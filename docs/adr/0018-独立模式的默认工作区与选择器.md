# 0018. 独立模式的默认工作区与选择器

- 状态：已采纳（修订 [ADR-0009](0009-独立模式的直连会话.md) 里「工作区留空 = 宿主默认位置」的默认值）
- 日期：2026-11-13

## 背景

独立模式要在某个工作区里建会话，[ADR-0009](0009-独立模式的直连会话.md) 让面板从宿主的工作区列表里挑一个，留空就用宿主默认位置。实际用起来两个问题：

1. 宿主默认位置是宿主自己初始化的第一个工作区，与本插件无关，微信会话会落在一个不相关项目的 cwd 里；手机上随手一问，回答的上下文却挂在前一个项目上。
2. 面板用原生 `<select>`，和 dsh 的模型选择器等下拉观感不一致，长路径挤在一行也不好读。

## 决策

**默认工作区固定成插件数据目录下的「微信会话」，面板的选择器换成 dsh 风格下拉。**

1. 默认工作区 = `$DSH_HOME/dsh-im-wechat`（可由 `dataDir` 覆盖），标题「微信会话」。插件在工作区服务接入时用 `workspaceRegistry.create(path, title)` 建出来：宿主对同一路径幂等，标题只在首次创建生效。建不出来时退回宿主默认位置：老宿主没有 `create` 时静默退回；目录不可写、宿主一直不返回（5 秒上限）时记一次面板错误，恢复成功后把这条横幅清掉。
2. 会话仍按 `workspaceId` 建，宿主据此决定 cwd，所以会话目录就是该工作区目录。`directWorkspaceId` 为空表示「用默认工作区」；面板选了别的就存那个 id。**选中的是默认工作区时也落成空值**，这样宿主重建工作区换了 id 仍跟随默认，不会钉在一个失效的 id 上。
3. 工作区列表 RPC 先等默认工作区建好再返回，避免首次打开下拉看不到「微信会话」。
4. 选择器用官方 `MenuSurface` 浮层 + portal + `position: fixed`：设置页外层可滚动，绝对定位会被祖先的 overflow 裁掉。每行显示标题与路径，选中项带勾；下方空间不够时向上翻转，左右夹回视口。键盘可用：上下 / Home / End 换焦点，Escape 收起并把焦点还给触发器，Tab 收起；取不到平台原语时退回朴素列表。

## 后果

- 微信会话固定落在一个中性目录，不再跟宿主默认工作区的项目混在一起。
- 代价一：插件加载时会在宿主的工区列表里多出一个「微信会话」，不用独立模式的人也会看到。
- 代价二（安全）：会话 cwd 就是插件数据目录，同一目录里还有 `login.json`（含 iLink 机器人的 `botToken`）与 `config.json`（均 `0600`）。会话里的文件工具能在该目录读到它们，一次成功的提示注入就可能把 token 带出去。`dataDir` 无法把状态与工作区拆开（两者同源），要消除这个暴露面得把状态目录上移一层或把工作区下沉到子目录，那会偏离本决策（按要求 cwd 就是 `$DSH_HOME/dsh-im-wechat`）。
- 宿主没有 `workspaceRegistry.create`（老版本）时退回「宿主默认位置」，行为与 ADR-0009 相同。
- 运行期在 dsh 里删掉这个工作区后，插件要重启（或工作区服务重新接入）才会重新登记；已绑定的会话照常提交，「重置绑定」后新建会话会失败并在面板记账。
