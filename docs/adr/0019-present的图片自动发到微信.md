# 0019. present 的图片自动发到微信

- 状态：已采纳（补 [ADR-0012](0012-出站快捷命令.md)：模型侧发图的另一条路）
- 日期：2026-11-13

## 背景

独立模式下模型拿到主人的图之后，主人说「把刚才那张图再发给我」。模型把附件副本写到本地、用 `present` 交付、并在正文里贴了图片 Markdown——这在 Web 端是对的，微信那头却只收到一段文字：`present` 是 Web/本机语义，Markdown 里的图片按 [ADR-0008](0008-微信原生Markdown与出站文本过滤.md) 会被剔掉。模型并不知道出站要走 `dsh-wechat-send image`（[ADR-0012](0012-出站快捷命令.md)），于是「发图失败」变成了静默的体验缺陷。

## 决策

**独立模式下，绑定会话里 `present` 的本地图片自动发到主人的微信。**

1. 触发点是 `deliverables/presented` 会话事件（`present` 工具落盘的事件），只处理独立模式 + 绑定的那个会话；接入核心时整段不进（提醒与交付由核心负责，ADR-0006）。
2. 只发**图片**：逐张 `stat` → ≤ 10 MiB → 按文件头认 png/jpeg/webp/gif；非图片、不存在、超限的文件静默跳过（微信桥不发文件）。一次最多 10 张，与 CLI 同量级。
3. 走与 CLI、交付相同的出站链路：`uploadImage` → `sendImage`，收件人恒为扫码登录的主人，`context_token` 缺失时不发并在面板记账。
4. 单张失败只记一条面板错误，不影响其余图片；一张都没发出去（且有个文件被跳过）时也记一条，避免「模型以为交付了、微信什么都没有」。
5. `dsh-wechat-send` 与 `/wechat image` 保持不变：显式发送、以及给脚本用的场景仍走它们。

## 后果

- 模型不需要知道微信出站怎么走，`present` 在 IM 会话里就是「发给对方」；主人问「把图发回来」能直接收到图。
- 代价：`present` 从「本机交付」变成「同时外发到微信」，在独立模式的会话里 present 一张图就等于发一条微信消息（与 CLI 的额度、窗口共享）。模型若同时 present 又调 CLI，会收到两遍——接受，优先保证不丢。
- 非图片文件仍不会出现在微信里（微信桥只声明发图），这类交付要靠 CLI 发文字说明。
