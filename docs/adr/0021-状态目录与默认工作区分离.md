# 0021. 状态目录与默认工作区分离

- 状态：已采纳（修订 [ADR-0002](0002-登录态与二维码呈现.md) 的登录态路径、[ADR-0009](0009-独立模式的直连会话.md) 的绑定文件路径、[ADR-0018](0018-独立模式的默认工作区与选择器.md) 的「默认工作区 = 数据目录」）
- 日期：2026-11-13

## 背景

原先一个目录同时扮演两个角色：`$DSH_HOME/dsh-im-wechat` 既是插件状态目录（登录态、面板设置、游标、`context_token`、独立模式绑定），又是独立模式默认工作区的 cwd（ADR-0018）。

这个重合带来两个问题：

1. **凭据暴露**（ADR-0018 已经把它记成「代价二」）：会话 cwd 就是这个目录，会话里的文件工具能读到同目录的 `login.json`（含 iLink 机器人的 `botToken`）。一次成功的提示注入就能把 token 带走。
2. **层次混乱**：`$DSH_HOME` 下本来只有宿主的框架目录（`profiles`、`storages`、`sessions`、`cache`…），插件私有状态混在里面，既看不出归属，也容易被当成宿主的一部分去清理或备份。

## 决策

**把两个角色拆成两个目录。**

1. **状态目录** → `$DSH_HOME/.dsh-im-wechat`（`STATE_DIR_NAME`，前导点表示「插件的私有状态」）。`resolveDataDir()` 跟随 `DSH_HOME`（缺省 `~/.dsh`），`dataDir` 静态配置仍可覆盖，优先级不变。
2. **默认工作区目录** → `$DSH_HOME/dsh-im-wechat`（`WORKSPACE_DIR_NAME`，不带点，保持原值），由 `resolveWorkspaceDir()` 解析。ADR-0018 的其余结论不变：仍由 `workspaceRegistry.create(path, title)` 幂等建出来、标题「微信会话」、建不出来就退回宿主默认位置。
3. `dataDir` 只改状态目录，**不再影响**默认工作区目录：那个目录是会话 cwd，语义上不属于「配置存哪儿」。要换工作区就选宿主里已有的工作区（`directWorkspaceId`）。
4. **不写迁移脚本**：插件从未正式发布，没有历史用户，也不存在要兼容的既有安装。本机环境由人把状态文件搬一次即可。
5. 隐私约束不变：状态目录 `0700`、文件 `0600`、原子写；不进日志、不进面板快照、不随包发布。

## 后果

- **ADR-0018 的「代价二（安全）」不再成立**：会话 cwd 里没有 `login.json`，也没有 `config.json`，会话里的文件工具再怎么被诱导也只能读到工作区自己的内容。ADR-0018 正文保留原文，这条结论由本篇取代。
- `$DSH_HOME` 下归属一眼可分：带点的 `.dsh-im-wechat` 是插件状态，`dsh-im-wechat` 是会话语义的工作区。
- 代价：本机已有安装要把状态文件从 `~/.dsh/dsh-im-wechat` 搬到 `~/.dsh/.dsh-im-wechat`；忘了搬就表现为「升级后要重新扫码登录」。工作区目录 `~/.dsh/dsh-im-wechat` 保留不动，宿主里那条 `微信会话` 工作区记录继续有效。
- 这个决策只影响落盘位置：`HOST_CONTRACT`、面板端点与 RPC 形状都没变。
