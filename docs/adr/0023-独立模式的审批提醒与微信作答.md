# 0023. 独立模式的审批提醒与微信作答

- 状态：已采纳（补齐 [ADR-0006](0006-问题提醒与长任务提醒归谁发.md) 在独立模式只覆盖「提问」的缺口）
- 日期：2026-11-15

## 背景

独立模式（未接入核心）一直只接管 `user-questions/request`：提问推到微信、主人在微信作答。工具授权走的是另一条 waterfall `approval/request`，本插件从未注册，所以需要授权的工具调用只会在 Web 端等人；主人在微信里长时间看不到提示，回合就这么卡着。

同时暴露两个可用性问题：

1. **没有开关**：提问与提醒只能跟着「接入微信」总开关一起开合，关掉就连收消息一起没了。
2. **一有提问就推**：用户通常正开着 Web 端，很多问题几十秒内就在 Web 端答掉了，微信那条提醒纯属打扰。

## 决策

**把审批也接进独立模式，并给两条提醒加同一个「等多久再提醒」窗口。**

1. **新增开关 `questionReminders`（默认开）与等待时间 `questionDelayMinutes`（默认 5 分钟，0–120，0 = 立即）**，落在 `config.json`，面板在「消息与提醒」区提供开关与分钟输入，`HOST_CONTRACT` 递增到 4。
2. **先让 Web 端拿请求，再等窗口**：进入监听器后立刻 `next()`，然后和等待计时器竞速。窗口内 Web 答完就一条微信都不发；Web 不在（`NO_PROVIDER`）或窗口到点才发提醒。提问与审批共用这个窗口。
3. **审批可以回微信处理**：提醒文案写明「回复「批准」或「拒绝」」。只认明确的整词（批准/同意/允许/通过/approve/allow/yes；拒绝/不允许/不批准/不同意/deny/reject/no），命中批准回 `allowed-once`、命中拒绝回 `rejected`，两者之外一律不认领，交给普通消息路径，**绝不猜**。这是宿主的失败关闭语义：`approval/request` 的缺省结局是 `unavailable`。
4. **只接管自己能负责的部分**：仍是只提醒根会话、只认扫码登录的主人、独立模式才生效（`ownFeaturesActive`）；接入核心后整段沉默（ADR-0006）。窗口内没人处理就把请求交回 Web，由 Web 或宿主默认值收尾。
5. **归属按「最后发的那条提醒」**：提问的单题自由输入会认领任意文本，不排序的话审批的「批准」会被它吞掉。两个 broker 各记一个发送序号，入站文本先给序号大的那一路。

## 后果

- 主人不在 Web 端时，工具授权也能从微信批掉，回合不再干等；在 Web 端时默认 5 分钟内不打扰。
- **安全边界扩大了一格**：微信消息现在能决定一次工具授权。约束是「只主人 + 只根会话 + 只认明确关键词 + 不代答 + 缺省失败关闭」；接入核心后这条路径不生效（核心自己决定授权）。ADR-0006 的「自有功能与核心互斥」不变。
- 等待窗口让审批最多晚 5 分钟才提醒，长回合会更慢；把 `questionDelayMinutes` 调成 0 即恢复「立刻提醒」。
- 新增两个模块：`approvals.ts`（审批 broker）与 `reminder-center.ts`（两个 broker + 设置）；`runtime.ts` 相应瘦身，面板设置动作移到 `panel-actions.ts`（文件规模规则）。
