# 0025. 独立模式会话的模型

- 状态：已采纳（补齐 [ADR-0009](0009-独立模式的直连会话.md) 没定的「独立模式用哪个模型」；不修订 0009 的其它结论）
- 日期：2026-11-15

## 背景

独立模式的直连会话由宿主的 `sessionController.create()` 建出来，用哪个模型由宿主的 `agentDefaultModel` 决定（DSH 的全局默认）。插件没有任何办法在新建会话时指定模型：`session.create` 的入参里没有模型字段。

于是主人想「微信这一侧固定用某个模型」（换个便宜的、或者带视觉的）时，只能去改 DSH 的全局默认模型，Web 端所有新会话跟着一起变。接入核心时不存在这个问题——那种模式下模型由核心选（ADR-0009），所以这一项只在独立模式里存在，也应该只在独立模式里可配置。

## 决策

1. **配置项** `directModel: { provider, model }`，与工作区、插话方式同层：静态配置写在 profile patch 里，面板改的落 `$DSH_HOME/.dsh-im-wechat/config.json`。缺省（字段缺席）跟随 DSH 的默认模型；面板清空写 `null`——与「没配过」区分开，否则清空后会回落到 profile 里的静态配置，看起来像没保存成功。
2. **生效时机：每次提交前钉一次（幂等），面板改完再立刻试一次**。
   - 提交前钉：新建的会话、以及宿主重启后还没 resume 的绑定会话都在这里补上——钉模型的调用点必须在 `prompt` 之前，否则这一轮还用 DSH 默认模型；
   - 面板改完立刻钉：就是 Web 端 `/model` 的效果，会话继续带着历史跑；
   - 同一个会话与同一个值只钉一次（钉成功过就记下来），所以既不会每来一条消息就写一条事件，也不会覆盖主人后来在 Web 端对这个会话做的切换；
   - 清空（跟随默认）只影响以后新建的会话：宿主把模型选择记成会话里的事件，撤不回来。面板在**这一次清空之后**提示「要回到 DSH 默认先重置绑定」，不常显、也不假装清空对当前会话生效。
3. **钉模型走 `agents.get(sessionId).model.select()`**，只往这个会话追加一条 `model/selection` 事件，DSH 的全局默认模型不动。**不走** `sessionController.selectModel`（否决方案见下）。
4. **候选来自宿主的模型目录** `sessionController.modelCatalog()`（新端点 `models.list`）：面板只让选目录里的 `provider/model`，保存时再按目录校验一次，目录里没有的组合拒绝保存。已保存的值不在目录里时，下拉把它补成一行原文并注明「已不在宿主的模型目录里」，不静默回退到默认——静默换模型比报错更难查。读不到目录（没有会话服务、宿主报错）时下拉禁用并显示原因，已配置的值照样保留。
   - 两种「目录里没有」要分开：**目录整体读不到**、以及**某个 provider 自己读失败**（宿主只把失败的 provider 放进 `failures`，整体仍算可用）时，面板标「未校验」、保存放行；不能把读不全的目录当成「模型已下架」去误拦一次无害的保存。
5. **面板交互**：下拉用官方 `MenuSurface` 那套（与工作区同一个组件 `MenuPicker`，第一项是「跟随 DSH 默认」并带出宿主当前的默认模型）；禁用判据与其它独立模式设置共用 `logic.ts` 的 `standaloneSettingsLocked`——接入核心、宿主版本对不上、有动作在跑时都锁住。
6. **契约**：`direct.set` 多了 `model` 字段（`null` 表示跟随默认）、新端点 `models.list`、`status.direct.model`，`HOST_CONTRACT` 与客户端 `REQUIRED_CONTRACT` 一起从 4 加到 5。

## 否决方案

- **`sessionController.selectModel`**：它除了给会话选模型，还会把选择写成 DSH 的全局默认模型（`agentDefaultModel.saveSelection`）。用它等于「改微信设置顺手改掉 Web 端所有新会话的默认模型」，与「不设置就跟随默认」的语义直接冲突。
- **自己用 `agents.create({ agentOptions })` 建会话**：能把模型带进去，但要重做工作区挂载、空会话复用、Agent preset 组合——等于把宿主的建会话逻辑抄一份，宿主改了就跟不上。
- **清空时把选择改写成「此刻的 DSH 默认」**：会话会被钉在那一刻的默认上，主人以后改 DSH 默认就不同步了，与「跟随默认」相反，所以不做。
- **面板里手写 `provider/model`**：宿主能列目录就必须从目录里选；手写会写出不存在的路由，还得自己解析 `provider/model` 的斜杠歧义。

## 后果

- 微信侧可以固定一个模型，Web 端的默认模型不受影响；清空后新会话回到跟随默认。
- 配置的模型被卸载或改名后：面板标「不在目录里」并要求重选，直连会话在下一条消息上拿到宿主的「模型不可用」错误（这条错误会发到微信）——比悄悄换个模型更容易发现。
- 「钉住」依赖会话持有活着的 Agent：宿主还没 resume 已绑定会话时改配置钉不进去，只记日志（值照常保存）；**下一条消息提交前会再钉一次**，所以不必重置绑定也能自愈（代价是宿主重启后这第一条消息用的是配置的模型，而不是主人上次在 Web 端给它换的那个）。
- 清空后已绑定的会话仍用它记下的模型；要与 DSH 默认一致得先「重置绑定」（面板在清空后提示一次）。
- 契约 4 → 5：新面板 + 旧 host 会提示重启（少一个下拉），旧面板 + 新 host 不受影响。
