# 0029. 独立模式的引用还原

- 状态：已采纳（补 0022 在独立模式没有消费者的缺口）
- 日期：2026-11-15

## 背景

[ADR-0009](0009-独立模式直连会话.md) 让独立模式把微信消息直接交给会话。入站的 `ref_msg`（微信的「引用回复」）在这条链路上一直没有消费者：[ADR-0022](0022-引用回复与回执-id-语义.md) 解决的是**核心**把引用认回哪一次交付（出站回执写平台 id、入站草稿带 `replyTo`），独立模式没有核心，引用在提交给会话之前就被丢掉了。

2026-11-15 的真机把代价摆出来了：主人在同一个会话里先后发了两份 PDF，几分钟后引用**第一份**问「这个文件的作者是谁？」。提问那条消息提交给会话的内容只有 `[{type:'text'}]`——引用没有跟过去。模型手里有两个文件句柄，认不出「这个文件」指哪一个，按最近的那份作答，答成了另一份的内容。

微信侧不缺这项能力：`ref_msg` 带被引用消息的服务端 id（`svr_id`；旧版是 `message_item.msg_id`），官方实现就是按入站 `message_id` 落一份内容缓存、按 `svr_id` 查回来。两套 id 同源。

## 决策

**独立模式把引用还原成一行中文标头，跟主人的文字一起提交；索引只在内存，不重新附带被引用的文件。**

```
[引用：文件 示例.pdf]
这个文件的作者是谁？
```

1. **按平台消息 id 记「这条消息带了什么」**：文件按下载后交给宿主的文件名记（与模型看到的句柄同名），图片记张数，文字记原文。键是最新一条入站消息的 `message_id`，查的是 `ref_msg.svr_id`，缺了退回 `message_item.msg_id`；两者都按 64 位整数无损解析，取整的 id 一律不认。
2. **索引只在内存、按条数兜住**：留最近 200 条消息的摘要，超出就挤掉最早那条；不设时效，进程活多久就有效多久，插件重启即失效。文件名与正文片段不进磁盘，也不进日志与面板快照。
3. **不重新附带被引用的文件**：模型对每个文件都会收到 `File "名字" (字节数, sha256:前 8 位): verbatim read-only copy saved at <路径>` 的句柄文本（宿主的 `fileHandleText`），指认清楚就够它去读对的那份。
4. **认不出来时不猜**：索引未命中就只用 `ref_msg.title` 的摘要；连标题都没有就不加标头，维持原来的行为。
5. **标头单独一个 part、带 `quote` 标记**：它和「请看这个文件」那类补提示同性质，不算主人写的字——补提示只看主人的文字（「引用 + 附件、没有文字」仍补一句），提交被拒后的纯文字重发也不带它。

## 否决的方案

- **引用时把被引用文件重新暂存一次**：宿主的 prompt 文件 part 只认本次上传铸造的一次性回执（`fileUploads.stage` 生成随机 UUID，消息一被宿主观察到就 `retire`），所以「再附一次」不能引用存量文件，得读本地副本再 `uploadStream` 一遍。它只在「句柄文本已经滚出上下文」时有价值，代价是要么把字节留在本地（与 [ADR-0028](0028-独立模式的文件入站.md) 的「插件不落盘」冲突），要么按宿主附件库的路径布局去读（宿主的内部实现）。先不做；真出现「很久以前引用的文件模型找不到」，按本地副本重新暂存再开一篇。
- **索引落盘**：能扛重启，但存的是消息正文片段与文件名，要另做清理与隐私边界，收益不成比例。
- **交给宿主解析**：宿主不认识微信的消息 id，也没有「按 id 取历史消息」的接口。
- **把引用当成独立的一条消息提交**：会话里会多出一条突兀的用户消息，还会打乱「一轮提问一轮回答」的配对，不如并进同一条。

## 后果

- 同一会话里连续发过多个附件时，「这个文件/这张图」不再只能靠猜：标头点名了被引用的那一份。
- 引用机器人自己发的消息，目前只能靠 `ref_msg.title`（桥没有把出站消息 id 记进索引）；插件重启后的引用、或超过 200 条之前的老消息，同样退回标题，可能仍指不清。两条都是可接受的残留。
- 索引只跟「当前这条绑定会话」的入站消息走：换了绑定会话（面板里改工作区、`/new`）之后引用旧会话里的附件，标头会点名一个在新会话里并不存在的文件——比不指认好，但主人要自己重发那份。
- 提交被拒后按纯文字重发时标头不跟着走（`textContent` 只取主人的文字）：那一次重发里「这个文件」会重新失去指认。宁可少一层上下文，也不把插件写的标头当成主人的话发出去。
- 标头是插件替主人写的一行，跟着这一条消息一起提交；只有引用、没有别的可交付内容时不提交，标头也不会单独成一条消息。
- `ref_msg` 里的 `partial_text`（客户端标记引用了某段选中的文字）暂不处理，整个被引用消息的摘要已经够指认。
