# 0030. 核心模式的文件上报

- 状态：已采纳（补 [ADR-0028](0028-独立模式的文件入站.md) 留下的「接入核心时文件照旧不处理」；独立模式的交付路径与预算不变）
- 日期：2026-11-15

## 背景

[ADR-0028](0028-独立模式的文件入站.md) 只做了独立模式，理由写得很明确：核心的 `OwnerMessageDraft` 没有文件字段、`protocol.features` 里也没有对应声明，桥不发明核心不认的字段，等核心有了能力再说。

2026-11-15 核心把这个能力加上了：`OwnerMessageDraft.files?: OwnerFile[]`（`name` / 可选 `mediaType` / 标准 base64 的 `data`），并在 `protocol.features` 里声明 `owner-files`；上限是 **最多 3 个、单文件解码后 ≤ 8 MiB、单条合计 ≤ 16 MiB**，`name` 不含 `/`、`\` 与控制字符，`data` 必须是合法 base64。于是「接入核心时文件不被处理」成了缺口：主人发给机器人的 PDF 在核心这边什么都不剩。

与图片（[ADR-0004](0004-图片入站与下载安全.md)）不同的是**失败代价**：核心对一条草稿只给一次判定，被拒就是整条消息连同文字一起丢，不是「少一个附件、文字照常」。所以桥不能把超限或格式不合的文件交给核心去裁，必须在上报前按同一组上限剔干净。

## 决策

**核心声明 `owner-files` 时，主人消息里的文件按核心 Schema 上报；桥在发送前按同一组上限先剔，独立模式一行不改。**

1. 能力：与 `imagesEnabled` 并列，`filesEnabled` 只由核心声明的 features 决定；没声明就完全不下文件、草稿不带 `files`——不能拿桥自己的版本替核心宣布能力（旧核心会忽略这个键，但那等于把一次白下载与一段无用字节留在进程里）。
2. 准入：`filesEnabled` + `senderIsOwner`，与图片同一道闸（ADR-0004）；没有 `owner-lookup` 就判不出主人，也就整条不下载。
3. 上限：直接用核心 Schema 那一组常量（3 个、单文件 8 MiB、合计 16 MiB），写在 `superagent/protocol.ts` 的协议副本里；下载仍复用 `downloadOwnerFiles` 与 ADR-0004 的边界（https、主机白名单、禁重定向、文件阶段 20 秒总时限）。单文件上限是这期新增的参数，独立模式不传，行为不变。
4. 桥侧先剔：`file_item.len` 预检（不够就按解密后的字节再判一次），超单文件的只丢那一个；合计放不下的从尾部丢，直到装得下，与图片「超了少一张」同一取舍。空文件不上报——核心 Schema 要求 `data` 至少 4 个字符，带上会连累整条草稿。
5. 剔掉的文件只记日志（名字 + 人话原因）：核心模式没有面向主人的回执渠道，ADR-0028 那套「回一句原因」属于独立模式的提交层。
6. 组装：`data` 用 `Buffer.from(bytes).toString('base64')`（标准字母表、带填充、长度是 4 的倍数），`name` 沿用独立模式那条清洗（去路径分隔符与控制字符、按字节截到 200 以内），`mediaType` 不填——核心只拿它展示，桥不猜类型。
7. 「只有文件、没有文字」算可交付：草稿 `text` 是空串，不再返回 `null`；`messageId`、`platformMessageId`、`replyTo` 的取值与纯文本消息完全一致，文件不影响引用目录。

## 否决的方案

- **交给核心兜底（先发再让它拒）**：整条消息连文字一起丢，是本决策要避免的事故形态。
- **桥自己定一套更宽的上限，靠核心裁到合规**：两边上限不一致时结果取决于哪一侧先发现，表现为「有时文字到了、有时什么都没有」，不可预期。
- **把文件降级成文字描述（名字 + 字节数）**：模型拿不到内容，「总结这份 PDF」永远做不成，等于没做。
- **填 `mediaType`**：核心不按它解析内容，一个猜出来的类型只会在展示上误导。
- **让核心把文件字节下发回来（出站方向）**：本期不需要，方向也相反。

## 后果

- 接入核心后，「总结这份 PDF」可用：文件字节进了核心，由核心按自己的策略交给会话。
- 代价：单条入站消息最坏在桥进程里驻留 16 MiB 明文加约 21.3 MB 的 base64 字符串，直到交给核心；文件阶段最多占用长轮询 20 秒（图片另算，与独立模式同）。
- 超过 8 MiB 的单个文件、以及合计装不下的尾部文件会被静默剔掉（只进日志）：主人看到的现象是「那个文件没到」，这是「宁可少一个文件，也不让整条消息都丢」的取舍。要改成明确回执，得先有核心模式下面向主人的一条回执通道。
- 独立模式不受影响：[ADR-0028](0028-独立模式的文件入站.md) 的宿主暂存回执、32 MiB 预算与失败提示全部照旧。
