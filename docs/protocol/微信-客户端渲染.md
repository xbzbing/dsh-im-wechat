# 微信客户端：Markdown 渲染

桥把交付原样交给客户端渲染，能不能渲染、渲染成什么样决定了要不要过滤——决策与过滤顺序见 [ADR-0008](../adr/0008-微信原生Markdown与出站文本过滤.md)。

## 渲染能力（2026-11-08 实测，PC + 手机）

用完整 Markdown 对照消息实测，**两端都能渲染**：

| 构造 | PC | 手机 |
| --- | --- | --- |
| 表格 | 渲染成真表格（含表头分隔线） | 同左 |
| 代码块 | 带语言标签与「复制」按钮 | 同左 |
| 行内代码 | 渲染 | 渲染 |
| 引用 | 有竖线 | 有竖线 |
| 分隔线 | 渲染 | 渲染 |
| 链接 | 渲染 | 渲染 |
| H1–H4 | 渲染 | 渲染 |
| 加粗 / 非中文斜体 | 渲染 | 渲染 |
| **软换行**（单个 `\n`） | **折叠成空格** | **保留换行** |

最初的结论是「PC 端渲染、手机端纯文本」，用完整对照复测后推翻：那次只用了「换行 / 空行 / 列表」做对照，被软换行差异带偏了。软换行差异是两端渲染器不同，不是 Markdown 支持与否——正文里的分行要交给 Markdown 语义（空行、列表、表格）表达，靠插空行伪造换行在 PC 端会失效。

## 官方出站过滤规则

官方 `openclaw-weixin` 的 `src/messaging/markdown-filter.ts` 印证同一前提：它不删格式，只剔掉客户端渲染不了的构造：

- 图片：整段丢弃；
- `#####` / `######`：去掉井号留文字；
- 包住中文的斜体：去掉标记；
- 删除线：去掉波浪线；
- 其余（代码块、行内代码、表格、链接、H1–H4、分隔线、加粗、非中文斜体）原样透传。

## 与官方的唯一差异

官方是**流式**过滤器，遇到任何 `~` 都直接吞掉（`~/x` 会变成 `/x`）；本插件发的是整条消息，只剥成对的 `~~…~~`，单独的波浪线原样保留。

## 未验证

- 超长交付按换行切分（默认 1800 字符/条）可能把表格或代码块切成两条，真机上还没遇到过需要按块切分的样本。
