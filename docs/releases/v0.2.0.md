## 升级须知

- **Node 24 起**：`engines.node` 从 `>=22.19` 收紧到 `>=24.0.0`。门禁只在 24 上跑，22 的测试运行器会把依赖 `AbortSignal.timeout` 的用例误判成取消，写 22 等于承诺一件没验证过的事。
- **DSH ≥ 0.2.2-rc.1**：新增 `engines.dsh`（`>=0.2.2-rc.1 <0.3.0`）。DSH 低于基线或升到 0.3 以后，安装与激活会被拦下并给出诊断；确实要试时用 `dsh plugin allow-version` 精确豁免（[ADR-0024](https://github.com/xbzbing/dsh-im-wechat/blob/master/docs/adr/0024-装机声明与版本基线.md)）。
- 已经装好的组合不受影响；升级本插件需要 Node 24 与 DSH 0.2.x。

## 主要变更

### 提醒可以等人了

- **提醒前等待**：提问与授权不再一出现就发微信。默认先在 Web 端等 5 分钟，这期间在 Web 端答完就一条都不发；到点还没答才提醒。等待时间 0–120 分钟，面板可改（0 = 立刻提醒）。
- **独立的提醒开关**：关掉它不影响收消息，只是提问与工具授权重新只走 Web 端。
- **面板能看见排队量**：运行概览里显示正在等你回答的问题数、等待授权的工具数。

### 工具授权可以在微信里处理

- 需要授权的工具会把工具名与原因发到微信，回「批准」或「拒绝」即可处理（[ADR-0023](https://github.com/xbzbing/dsh-im-wechat/blob/master/docs/adr/0023-独立模式的审批提醒与微信作答.md)）。
- **只认明确的关键词**：批准/同意/approve/yes，拒绝/不批准/不同意/deny/reject/no，不收单字母 `y`/`n`；说别的话不会替你决定，请求原样交回 Web 端。
- **多笔授权可指定**：提醒带编号（`需要你授权 #3：bash`），回复可带编号（`批准 3`）；不带编号时批最后一条，结算后回一条「已批准：bash（#3）」，批错了当场能看出来。
- **边界没放宽**：只有扫码登录的主人、只有根会话、只有没接核心的独立模式能走这条路；接入 `dsh-my-superagent` 后整段沉默，授权仍由核心决策。

### 更少误报与重复

- **回复不再串台**：提问的自由文字作答与审批的「批准」共用一套待答机制，按最后发出的那条提醒归属；接上核心后不再重复提醒。
- **重启不重批**：最近 50 条已处理的提醒回复落了盘，宕机重投同一条「批准」不会批掉一笔新授权。
- **提醒单独节流**：6 条/分钟、最小间隔 2 秒，超了就把请求交回 Web 端——排队到点才发出的提醒已经过时，更容易批错。
- **面板不再骗人**：接入我的超级助理后，只属于独立模式的设置（提醒开关、提醒前等待、长任务阈值）在面板上锁住并说明原因，不会让人改完发现没反应。

### 顺手修掉的

- 登录失败时不再显示「二维码已过期」，改说登录未完成并给出宿主原因。
- iLink 发送请求带单次超时；网络失败的提示不再拼底层异常。
- `context_token` 只缓存主人会话的、并加容量上限，不会被无关群消息冲掉。
- 桥适配补齐配额、截止时间、幂等与发送健康状态；提交超时的文案改成「可能已进入会话」，不再让人误以为一定没发出去。
- 关闭插件或接入核心期间，不再遗留待答的提问。

## English

## Upgrade notes

- **Node 24 and newer**: `engines.node` moves from `>=22.19` to `>=24.0.0`. CI only runs 24, and Node 22's test runner reports `AbortSignal.timeout` cases as cancelled, so claiming 22 support was never verified.
- **DSH 0.2.2-rc.1 and newer**: a new `engines.dsh` range (`>=0.2.2-rc.1 <0.3.0`). Older DSH releases and anything past 0.3 are blocked at install and activation with a clear diagnostic; grant an exact-version exemption with `dsh plugin allow-version` if you really want to try.
- Existing installations keep working; upgrading this plugin needs Node 24 and DSH 0.2.x.

## Highlights

### Reminders can wait now

- **Wait before reminding**: questions and approvals no longer message WeChat immediately. By default the plugin waits 5 minutes for the Web UI to answer; if it does, nothing is sent. The window is configurable from 0 to 120 minutes (0 = remind right away).
- **A dedicated reminder switch**: turning it off keeps messages flowing and sends questions and approvals back to the Web UI only.
- **Pending counts in the panel**: the runtime overview shows how many questions await your answer and how many tool approvals are pending.

### Approve tools from WeChat

- An approval request arrives with the tool name and reason; reply 「批准」/「拒绝」 (approve/reject) to handle it.
- **Explicit keywords only**: approve/同意/yes, reject/不批准/deny/no; single letters `y`/`n` are refused. Anything else hands the request back to the Web UI instead of guessing.
- **Multiple approvals are numbered**: reminders read `需要你授权 #3：bash`, replies may carry the number (`批准 3`); without one the latest pending request is used, and a receipt reports which one was approved.
- **The boundary did not move**: owner only, root session only, standalone mode only. Once `dsh-my-superagent` is attached this path goes quiet and the core decides approvals.

### Fewer false alarms and duplicates

- Replies no longer cross wires: free-text answers and approval keywords share one pending mechanism ordered by the last reminder sent.
- Redelivered messages cannot re-approve: the last 50 consumed reminder replies are persisted, so a restart that replays a message id does not approve a new request.
- Reminders are throttled separately (6 per minute, 2 second minimum gap); past that the request returns to the Web UI, because a stale reminder invites wrong approvals.
- The panel stops lying: settings that only apply to standalone mode lock themselves with an explanation once the core is attached.

### Fixed along the way

- A failed login no longer shows "QR code expired"; it reports login as unfinished with the host's reason.
- iLink sends carry a per-request timeout, and network errors no longer append raw exceptions.
- `context_token` is cached only for owner conversations and bounded in size.
- The bridge gained quota, deadline, idempotency and send-health handling; a submit timeout now says the message may already have entered the session.
- Disabling the plugin or attaching the core no longer leaves pending questions behind.

## Install

```bash
# Stable (npm)
dsh plugin --profile web add dsh-im-wechat@0.2.0

# The same version as a GitHub Release asset
dsh plugin --profile web add https://github.com/xbzbing/dsh-im-wechat/releases/download/v0.2.0/dsh-im-wechat-0.2.0.tgz
```

To upgrade an existing install, remove the plugin, wait a few seconds, then add it back. Configuration and login state stay in `$DSH_HOME/.dsh-im-wechat/`; no need to scan the QR code again.
