## 主要变更

- **回复下方可以带上状态信息了**：面板「独立模式」里新增开关 **回复附加状态信息**（默认关）。打开后，独立模式直连会话的每条回答末尾多一行 `模型 deepseek-reasoner · 推理 high · 消耗 12K tokens · 时间 11-05 09:07`——模型取这一轮助手消息自己记录的来源，推理等级取当前选择，token 按回合累加，时间是发送时刻。
- **统计口径按「这一轮真的花了多少」算**：同一个回合里的多步工具调用累加；失败、被中止、被重试的那次调用（没有落成消息，但 token 真的产生了）也算进去；压缩与子代理会话不在本会话的事件里，不计入。推理等级只在它记录的模型与本轮消息一致时才显示——`/new` 换了会话、清空模型选择、或接入核心期间漏收了选择事件，都宁可省略这一项，也不挂上一个别的模型的等级。
- **分条不会顶破单条上限**：状态行只接在最后一条上，切分前先把它自己的字节数从 `maxText` 里扣掉；扣完剩不下多少（阈值配得极小、模型 id 又很长）就不扣，宁可最后一条略超，也不把正文拆成碎片。模型 id 与等级 id 还会被压成单行，换行与控制字符不会把状态行拆开。
- **接入核心时不加**：核心的交付本来就带自己的状态行（模型、思考、上下文、用时），两边都加就是同一条回复挂两套统计。接入核心后这个开关在面板上锁住并标出原因。
- **内部**：新增 `src/host/reply-status.ts`（按回合累计用量、拼状态行、分条策略集中在一处），面板契约版本 `HOST_CONTRACT` / `REQUIRED_CONTRACT` 一起升到 9；验收流程文档补上「先 `npm run build` 再装」（`lib/` 是产物、`dsh plugin add` 只装不构建），卸载与重装之间的间隔改成 3–5 秒。

## English

- **Replies can carry a status line**: the standalone section of the panel gains **Reply status** (off by default). When on, every reply from the standalone direct session ends with `模型 deepseek-reasoner · 推理 high · 消耗 12K tokens · 时间 11-05 09:07` — the model comes from the assistant message's own source, the reasoning effort from the current selection, tokens are summed per turn, and the time is the send time.
- **Counting reflects what the turn really spent**: multi-step tool calls in one turn add up; failed, aborted or retried attempts (which commit no message but do consume tokens) are included; compaction and subagent sessions live on other event streams and are not counted. The reasoning effort is shown only when the model recorded with the selection matches the message — after `/new`, after clearing the model choice, or when a selection event was missed while the core was in charge, the item is omitted rather than borrowed from another model.
- **Splitting never breaks the per-message limit**: the status line rides on the last part only, and its own byte count is subtracted from `maxText` before splitting. When too little room is left (a tiny threshold and a long model id) nothing is subtracted — a slightly long last part beats shredding the body. Model and effort ids are flattened to one line so control characters cannot split the status line.
- **Not added when the core is in charge**: core deliveries already carry their own status line (model, reasoning, context, duration); adding a second one would hang two sets of numbers on one reply. The switch is locked in the panel with the reason shown whenever the core is connected.
- **Internal**: new `src/host/reply-status.ts` (per-turn usage accumulation, status line rendering and the split policy in one place); the panel contract version `HOST_CONTRACT` / `REQUIRED_CONTRACT` bumped to 9; the acceptance docs now say to run `npm run build` before installing (`lib/` is a build artifact and `dsh plugin add` does not build), and the gap between uninstall and install is 3–5 seconds.
