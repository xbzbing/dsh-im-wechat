## 主要变更

- **提醒文案统一为「长程任务」**：面板上的「提醒阈值（分钟）」改名为 **「长程任务提醒阈值（分钟）」**，微信里发出的提醒标题、面板与 README 中所有用户可见的「长任务提醒」一并改为「长程任务提醒」，与如流桥的叫法一致。
- **新增「失败任务提醒」开关（默认开）**：面板提醒区在阈值下方多一行开关。开着时，报错、被拦下、非本人中止的回合**不看阈值立刻提醒**（与以前一致）；关掉后失败也保持安静，且**不会降级**成按阈值的完成提醒——同一次失败不会在阈值到点时以「已完成」的面目再出现一次。本人主动停的回合在两种开关下都不提醒。
- **完成提醒与失败提醒各走各的开关**：完成提醒仍看「自有功能生效 + 超过阈值」；两个开关都关才完全安静。max-tokens 仍归为完成路径，按阈值处理（既定分类，未变）。
- **配置**：新增 `failureReminders`——profile 的 `cordis.patch.yml` 给静态默认，面板改的值落在 `$DSH_HOME/.dsh-im-wechat/config.json`（`0600`）并优先于它；旧配置文件没有这个字段，读回为开，升级后行为不变；写坏的值也回落到开（这是通知不是授权，静默关掉比多一条提醒更难发现）。
- **内部**：面板 RPC 契约 `HOST_CONTRACT` / `REQUIRED_CONTRACT` 一起升到 10（`longtask.set` 接受 `{minutes?, failureReminders?}`，新旧面板与 host 互认）；新增 ADR-0031 取代 0011 的「失败关不掉」，两篇互标、索引同步；README 与 AGENTS 的失败提醒不变量改成「两个开关」。

## English

- **Naming unified around “long-task”**: the panel row **Reminder threshold (minutes)** is now **Long-task reminder threshold (minutes)**, and every user-visible “长任务提醒” in the WeChat reminder title, the panel and the README is now “长程任务提醒”, matching the InfoFlow bridge.
- **New Failed-task reminders switch (on by default)**: one more row under the threshold in the reminder section. While on, a failed turn (error, blocked, aborted by someone else) is reported immediately regardless of the threshold — same as before. While off, failures stay quiet and are **not** downgraded into a threshold-based completion reminder, so the same failure cannot show up later wearing a “completed” face. Turns the owner stopped themselves are never reported, in either position.
- **Completion and failure now have separate switches**: completion reminders still depend on “own features active + over the threshold”; only both switches off means complete silence. max-tokens stays on the completion path under the threshold rule (unchanged classification).
- **Configuration**: new `failureReminders` — the profile `cordis.patch.yml` provides the static default, panel edits land in `$DSH_HOME/.dsh-im-wechat/config.json` (`0600`) and take precedence; older config files lack the field and read back as on, so upgrading changes nothing; a corrupted value also falls back to on (this is a notification, not an authorization — staying silent is harder to notice than one extra message).
- **Internal**: panel RPC contract `HOST_CONTRACT` / `REQUIRED_CONTRACT` bumped to 10 (`longtask.set` accepts `{minutes?, failureReminders?}`; old and new panels/hosts interoperate); new ADR-0031 supersedes 0011’s “failures cannot be silenced”, cross-linked in both and reflected in the index; README and AGENTS now describe the two-switch invariant.
